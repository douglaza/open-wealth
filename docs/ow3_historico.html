Snapshots Diários, Idempotência e Construção de Séries Históricas

Na Fase 1 e 2, o Open Wealth era capaz de conectar na Pluggy, valorizar posições e mostrar a foto de hoje. Mas finanças pessoais exigem perspectiva: meu patrimônio está crescendo? Quanto rendeu nos últimos 90 dias? A Fase 3 constrói a infraestrutura de séries temporais com garantia de idempotência diária e suporte dual SQLite/PostgreSQL.

1

O Problema: Foto Estática vs. Filme Histórico

Abordagem Ingênua (Overwrite)

Se a cada sincronização o banco apenas atualizar uma tabela current_balance sobrescrevendo os valores anteriores, perde-se completamente o histórico. É impossível saber se o usuário acumulou patrimônio ou se descapitalizou.

Abordagem Open Wealth (Snapshots Imutáveis)

Cada dia fecha com um Snapshot Patrimonial imutável contendo todas as contas e ativos abertos. Isso cria uma linha do tempo contínua que viabiliza curvas de drawdown, rentabilidade acumulada e comparações macroeconômicas.

2

Modelagem de Dados e Schema Relacional

O repositório SnapshotRepository encapsula o gerenciamento de schema relacional e migrações autônomas na inicialização:

Tabela: snapshots
  • • id INTEGER PK AUTOINCREMENT
  • • date DATE NOT NULL
  • • institution TEXT NOT NULL
  • • total REAL NOT NULL
  • • created_at TIMESTAMP
  • • UNIQUE(date, institution)
Tabela: accounts
  • • id INTEGER PK AUTOINCREMENT
  • • snapshot_id FK -> snapshots.id
  • • name TEXT NOT NULL
  • • category TEXT (banco/cartao)
  • • balance REAL NOT NULL
Tabela: investments
  • • id INTEGER PK AUTOINCREMENT
  • • snapshot_id FK -> snapshots.id
  • • name TEXT NOT NULL
  • • type TEXT (EQUITY, FIXED_INCOME...)
  • • value REAL (Cascata de Valoração)
3

A Regra de Ouro: Idempotência Diária

⚡ Por que a idempotência é inegociável em Open Finance?

Se o usuário disparar a sincronização manual pelo dashboard ou via cron jobs múltiplas vezes no mesmo dia, os saldos não podem duplicar. O Open Wealth adota verificação preventiva: se já existe um snapshot para aquele par (data, instituição), o sync pula a chamada e emite o log snapshot_skipped.

app/services/sync.py • Verificação de Idempotência Python 3.12 
today = datetime.now(timezone.utc).date()

# 1. Verifica existência prévia antes de chamar a API externa
if snapshot_repo.has_snapshot_for_date(today, institution=item.institution_name):
    logger.info(
        "snapshot_skipped",
        date=str(today),
        institution=item.institution_name,
        reason="already_synced_today"
    )
    return False

# 2. Executa coleta e grava atomicamente com cascata de valoração
snapshot = build_daily_snapshot(item, accounts, investments)
snapshot_repo.save(snapshot)
logger.info("snapshot_saved", date=str(today), total=snapshot.total)
return True

def calculate_growth_rate(start_val: float, end_val: float) -> float:
    """Calcula taxa percentual com proteção estrita contra divisão por zero."""
    if start_val <= 0.0:
        return 0.0
    return round(((end_val - start_val) / start_val) * 100.0, 2)

def get_evolution_series(repo: SnapshotRepository, days: int = 90) -> list[dict]:
    snapshots = repo.get_history(limit_days=days)
    return [
        {"date": str(s.date), "total": s.total, "institution": s.institution}
        for s in snapshots
    ]

Funcionalidade: Privacy Mode (Blur CSS) CSS Blur Filter
