Sincronização Agendada, Gestão de Lifespan e Logs Estruturados

Nenhum usuário quer ter que abrir o terminal ou clicar em "Sincronizar" todos os dias para manter seu patrimônio atualizado. A Fase 6 entrega a Automação Completa da aplicação: um orquestrador agendado via APScheduler integrado ao ciclo de vida do FastAPI, garantindo execução diária no fuso brasileiro, resiliência contra falhas de rede e auditoria via logs JSON.

1

O Desafio Operacional da Sincronização Diária

Janela Operacional Ideal (09:00 BRT)

As instituições financeiras fecham os saldos de D-1 durante a madrugada. Às 09:00 em America/Sao_Paulo, os saldos bancários e posições de renda fixa já foram consolidados pelos custodiantes, tornando esse o momento perfeito para disparar o sync sem pegar dados parciais.

Tolerância a Falhas e Logs JSON

APIs de Open Finance podem apresentar latências ou instabilidades momentâneas. O orquestrador não pode derrubar a aplicação se uma requisição falhar: ele captura exceções, gera logs estruturados com eventos e agenda a próxima tentativa sem interrupção do serviço.

2

Implementação: app/core/scheduler.py

Utilizamos o AsyncIOScheduler da biblioteca APScheduler, totalmente compatível com o loop assíncrono do FastAPI e Uvicorn:

app/core/scheduler.py • Orquestrador Assíncrono com APScheduler Python 3.12 
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from apscheduler.triggers.cron import CronTrigger
from zoneinfo import ZoneInfo

scheduler = AsyncIOScheduler(timezone=ZoneInfo("America/Sao_Paulo"))

async def scheduled_sync_job() -> None:
    """Job agendado executado diariamente às 09:00."""
    logger.info("scheduler_job_started", trigger="cron_daily_09h")
    try:
        service = get_sync_service()
        result = await service.execute_sync()
        logger.info("scheduler_job_finished", result=result)
    except Exception as exc:
        logger.error("scheduler_job_failed", error=str(exc))

def start_scheduler() -> None:
    # Execução diária às 09:00 (Segunda a Domingo)
    trigger = CronTrigger(hour=9, minute=0, timezone=ZoneInfo("America/Sao_Paulo"))
    scheduler.add_job(
        scheduled_sync_job,
        trigger=trigger,
        id="daily_open_finance_sync",
        replace_existing=True
    )
    scheduler.start()
    logger.info("scheduler_started", schedule="09:00 America/Sao_Paulo")
3

Gerenciamento de Ciclo de Vida (Lifespan Context)

Em vez de eventos legados @app.on_event("startup"), o Open Wealth segue as melhores práticas do FastAPI moderno usando @asynccontextmanager para garantir inicialização e encerramento gracioso (graceful shutdown) de threads e conexões:

main.py • Lifespan Assíncrono com Shutdown Seguro Python 3.12 
@asynccontextmanager
async def lifespan(app: FastAPI):
    # STARTUP: Inicializa banco, migrações e dispara o scheduler
    init_db()
    start_scheduler()
    yield
    # SHUTDOWN: Encerra jobs pendentes sem corromper transações
    if scheduler.running:
        scheduler.shutdown(wait=False)
        logger.info("scheduler_shutdown_complete")

app = FastAPI(title="Open Wealth API", lifespan=lifespan)

Operação Contínua como Serviço Linux (Systemd)

Para manter o backend rodando 24/7 na máquina do desenvolvedor ou servidor Linux, basta configurar o serviço systemd em /etc/systemd/system/open-wealth.service: 

[Unit]
Description=Open Wealth FastAPI & Scheduler Service
After=network.target

[Service]
Type=simple
User=douglaza
WorkingDirectory=/home/douglaza/Documentos/open-wealth
ExecStart=/home/douglaza/Documentos/open-wealth/.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5
Environment="PATH=/home/douglaza/Documentos/open-wealth/.venv/bin"

[Install]
WantedBy=multi-user.target
